账号验证管家 1.10.0 正式版：
历史记录 → 管理 → 登录并生成 CPA / sub2api。选择 ChatGPT / OpenAI（Codex）或 Claude / Anthropic，再选历史账号自动填充或官方网页手动登录授权。
账号须使用实际登录邮箱，授权结果须与所选历史账号一致。自动模式只填写账号、密码与验证器动态 2FA；在网页点击继续、完成邮箱验证码/人机验证并确认授权。Claude 采用邮箱链接等登录方式时仍需在官方网页完成。
登录成功后可分别生成 CPA JSON 和 sub2api JSON。文件含可用登录令牌，不含账号密码或 2FA 密钥；这与原有密码加密 .avmx 历史备份不同。妥善保管 JSON，不要公开分享。
登录结果仅在内存保留，不写入历史；关闭登录窗口、记录删除/到期/替换、15 分钟会话超时或令牌到期即失效。导出文件是独立副本，不随源记录删除。
解析、验证码和本地历史继续离线运行；仅主动登录时连接官方网页和官方授权服务。
Windows 自动模式需要已安装 Edge 或 Chrome，使用独立临时浏览器窗口；手动模式打开系统默认浏览器。
Android 自动模式需要 Android 9+ 与官方 Chrome / Edge，首次需在系统启用本应用自动填充服务，Chrome 中选择使用其他自动填充服务，点击建议后填写；手动登录支持 Android 8+。不改变手机系统设置，需由用户在设置中选择。
如果未自动返回，复制网页地址栏中完整 localhost 回调地址回到管家完成登录；不要把回调或文件发送给他人。
Windows 与 Android 1.10.0 同步正式发布。Windows OpenAI 真实登录及两种 JSON 保存已通过；Claude 按用户要求停止真实账号核验。实际 CPA / sub2api 服务端导入尚未验收。

账号验证管家  v1.10.0
===========================

运行方式
双击“账号验证管家.exe”即可运行，无需安装，无需管理员权限。
适用于 Windows 10 / 11（使用系统自带的 .NET Framework 4.x）。

使用方法
1. 粘贴账号记录、纯 2FA 密钥或 Authenticator URI，程序会智能识别输入类型。
   账号记录的格式为“账号----密码----2FA密钥”，最后一项也可填写完整 otpauth:// URI。
   默认选择“智能识别”：账号记录中连续三个及以上的标点或符号作为候选分隔符。
   例如 ---、=====、|||、***、###、！！！ 或混合符号 |#|，两处可以不同。
   如果需要手动指定，点击“手动设置”，在“分隔符”中填写即可。
2. 点击“识别并生成”，或按 Ctrl+Enter。
   如果已经复制好记录，也可直接点击“粘贴并解析”。
3. 点击账号、密码、密钥右侧的“复制”，或点击“复制验证码”。
   验证码复制后是连续的六位数字，不含界面上的分组空格。
4. 右下角“复制全部”可复制带标签的四行内容。
5. 点击“清空内容”或按 Esc，清除当前输入和结果。

新版界面
- 上方输入，下方左侧集中显示登录信息，右侧显示验证码和倒计时。
- 自动 / 手动切换为直接选择按钮；仅在手动模式显示分隔符输入框。
- 复制成功后，按钮短暂显示“已复制”，窗口底部也会给出提示。
- 窗口支持缩放；Tab 可切换控件，Enter 或空格可操作按钮。

智能 2FA 解析
- 纯密钥：直接粘贴 Base32，支持小写、分组空白和末尾 = 填充，默认 SHA1 / 6 位 / 30 秒。
- Authenticator URI：支持 otpauth://totp/ 和 otpauth://hotp/，识别 secret、issuer、algorithm、digits、period 和 counter。
- 支持服务名和账号的百分号编码，包括中文；issuer 参数优先于标签前缀。
- 支持 SHA1、SHA256、SHA512，6 位或 8 位数字，TOTP 周期采用 URI 指定的正整数秒。
- HOTP 按 URI 的非负 counter 生成，不随时间变化。点击“下一个”才递增并加密保存；复制不会递增。
- 未提供账号或密码时会显示“未提供”，对应复制按钮停用；整组复制只包含已提供的字段和验证码。
- 支持文本和二维码图片，不支持 otpauth-migration:// 批量迁移 URI/二维码。

最近 10 条历史记录
- 成功识别后自动保存最近 10 条记录，按识别时间从新到旧排列，重启后仍保留。
- 完全相同的账号、密码和密钥再次识别时置顶，不重复占用条目；同账号的不同密码或密钥视为不同记录。
- 点击历史记录的账号名称或时间，可恢复到主界面，查看并复制该记录的各项内容。
- 每条历史记录提供“账号 / 密码 / 验证码 / 整组”四个快捷复制按钮。
- “整组”复制已提供的账号、密码和当前 2FA 验证码，不包含 2FA 密钥。
- TOTP 在点击复制时按当前时间重新计算；HOTP 使用已保存的当前计数器，不会因复制而递增。
- 顶部“历史记录”按钮切换到历史页；“返回解析”或 Esc 返回解析页。窗口宽度保持不变，点击记录也会返回解析页。
- 历史按空间排成一列或两列，超过可见范围时可纵向滚动查看。
- “清空内容”只清除当前窗口的输入和结果；“清空历史记录”经确认后清除全部历史。
- 旧版未保存历史，因此无法补回升级前的识别记录。

输入示例（虚构测试数据）
demo@example.com----Demo%_Password----GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ
demo@example.com------Demo%_Password-----GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ
demo@example.com|||DemoPassword===GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ
GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ
otpauth://totp/Example:demo%40example.com?secret=GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ&issuer=Example&digits=8&period=60

格式规则
- 自动模式：连续至少三个符号才会被识别；字母、数字、空白不会被自动视为分隔符。
- 自动模式支持全角符号、横线、表情符号和混合符号串，两处的符号和数量可以不同。
- 自动识别一段符号时，优先取其中连续重复至少三次的部分，保留相邻的其他密码符号。
  例如 pass*----- 中的 * 会保留在密码中；没有重复部分的混合符号串则整段识别。
- 使用第一处和最后一处分隔符，因此密码内部的符号串会保留。
- 2FA 密钥末尾的 Base32 填充 = 不会被当作最后一处分隔符。
- 手动模式：按填写内容原样匹配，支持单字符、多字符、符号或文本，不使用正则表达式。
  例如只有两个减号 -- 的记录，请使用手动模式并填写 --。
- 密码符号与分隔符相连而无法确定边界时，请使用手动模式；手动模式保留分隔符之外的字符。
- 如果密码本身含有手动分隔符，按第一处与最后一处匹配；同一字符连在一起仍可能有歧义。
- 保留密码的大小写、特殊字符和首尾空格，不做替换。
- 2FA 密钥采用 Base32，支持小写、分组空白及标准末尾 = 填充。
- 一次解析一条记录；多行输入会提示错误。
- 修改输入后，旧结果立即失效，请重新解析。
- 切换识别模式或修改手动分隔符后，旧结果也会失效，请重新解析。
- 解析成功时会提示本次使用的分隔符，便于核对。

验证码
TOTP 采用 RFC 6238，默认 HMAC-SHA1、6 位、30 秒周期、Unix 时间起点；URI 可指定算法、位数和周期。
HOTP 使用计数器生成，界面明确显示计数器，并提供“下一个”按钮。
界面按解析结果显示参数。复制 TOTP 时重新计算当前值，复制 HOTP 时读取最新已保存计数器。
电脑时间需要准确；如验证码无效，请先检查系统时间。
规范参考：https://www.rfc-editor.org/rfc/rfc6238
URI 参考：https://github.com/google/google-authenticator/wiki/Key-Uri-Format

本地数据
解析与验证码离线运行，登录按需联网。历史记录保存在本机，使用 Windows 当前用户的 DPAPI 加密保护账号、密码和 2FA 密钥。
文件位置：%LOCALAPPDATA%\AccountVerificationManager\history.bin
历史文件通常只能在同一设备、同一 Windows 用户账户下解密，不作为跨设备备份格式。
仅保存最近 10 条成功识别记录及其 OTP 参数，不保存验证码。界面启动时不主动展开某条记录的密码。
兼容 v1.4 旧版加密历史，新的保存操作会自动升级格式。
若历史文件损坏或无法解密，会提示错误并保留原文件；明确清空历史后可以重新保存。
“清空内容”不修改系统剪贴板，也不删除历史记录。
复制操作会将所选内容放入 Windows 剪贴板，受系统剪贴板历史和同步设置影响。

在 PowerShell 中运行 .\build.ps1，生成 release 目录中的程序并执行核心测试。
