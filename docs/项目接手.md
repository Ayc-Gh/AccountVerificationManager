后续更新：两端当前已在本地升级至 1.8.0，新增 [便捷更换 2FA](v1.8.0更换2FA.md)，保留账号、密码和历史名称；Android 同时支持账号记录末项 URI 以保留更换后的参数。此前 1.7.2 优化 Windows 改名弹窗，见 [1.7.2 改名弹窗](v1.7.2改名弹窗.md)。Windows 收窄窗口并改为解析、历史同窗口切换，见 [1.7.1 界面验证](v1.7.1界面验证.md)；两端历史命名见 [1.7.0 更新与验证](v1.7.0更新与验证.md)。保留二维码识别和既有应用端安全配置。下文版本与差异表记录接手时的基线。

账号验证管家是离线的账号记录与 2FA 解析工具，提供 Windows 和 Android 两个原生客户端。两段历史会话的需求、源码、版本和发布关系已归入本项目。后续在本仓库统一维护，沿用 [Ayc-Gh/AccountVerificationManager](https://github.com/Ayc-Gh/AccountVerificationManager) 仓库。

## 架构和数据流

Windows：`Program.cs` 接收输入，经 `SmartParser` 分类，账号记录由 `AccountParser` 按第一处与最后一处分隔符拆分；`Base32` 验证密钥，`Totp` 生成 TOTP 或 HOTP。`AccountData` 携带实际算法、位数、周期和计数器。`HistoryStore` 将完整参数保存为二进制版本 2，兼容读取版本 1，使用当前 Windows 用户 DPAPI 加密、命名互斥锁和原子替换处理持久化及多窗口操作。

Android：`MainActivity` 提供原生滚动界面和解析、历史两个页面；`core/SmartParser` 分类，`AuthenticatorUri` 严格解析单个 TOTP URI，`OtpParameters` 和 `Totp` 计算验证码。`HistoryRepository` 用单线程队列执行磁盘与 Keystore 操作，主线程接收结果；`HistoryCodec` 读 v1、写 v2；`HistoryCipher` 与 `EncryptedHistoryStore` 用 Keystore AES-256-GCM 和 AtomicFile 保存历史。旋转只在内存保留结果，不把凭据写入 Activity Bundle。

两端共享产品规则和发布仓库，核心逻辑分别用 C#、Java 实现，目前没有共享二进制库。Windows 历史绑定当前系统用户，Android 历史绑定应用与本机 Keystore；不能把一端的密文文件复制给另一端使用。

## 功能覆盖与实际差异

| 能力 | Windows v1.5.0 | Android v1.1.0 |
| --- | --- | --- |
| 账号记录、独立 Base32 密钥、独立 TOTP URI | 支持 | 支持 |
| 连续至少三个符号自动分隔、手动按字面匹配 | 支持 | 支持 |
| SHA1、SHA256、SHA512；6 或 8 位；正整数周期 | 支持 | 支持 |
| 输入改变清旧结果、复制时重新计算、十条加密历史 | 支持 | 支持 |
| 账号记录末项直接放完整 URI | 支持，保留外层账号密码 | 尚不支持，末项仍按 Base32 验证 |
| HOTP URI 和持久化计数器 | 支持，点击“下一个”才递增；复制不递增 | 明确拒绝 |
| 标签发行方与 issuer 冲突 | issuer 查询参数优先 | 明确拒绝冲突 |
| URI 查询参数中的原始加号 | 按空格解码；保留加号需 `%2B` | 保留为加号 |
| 纯 Base32 输入与手动分隔符发生重叠 | 先识别纯密钥 | 存在两处手动分隔时先按记录解析 |
| 最大输入长度 | 16,384 个 UTF-16 字符（清理后） | 32,768 个 UTF-16 字符（原输入） |
| 二维码、批量迁移 URI、云同步、跨端历史迁移 | 未实现 | 未实现 |

这些差异在本次归并中保留，没有顺带增加 HOTP、迁移数据或改变输入语义。下一次要对齐跨端体验时，优先统一解析规范与边界用例，再决定扩展 Android HOTP 和账号记录末项 URI。

## 构建和验证

Windows 使用系统 .NET Framework 4.x 编译器与 Windows Forms，无第三方运行库。Android 使用 JDK 21、Android SDK platform 37、build-tools 37.0.0、AGP 9.3.1、Gradle 9.6.1；Java 源码兼容级别为 17，最低 API 26，正式包名 `cn.local.accountmanager`。

```powershell
# 先进入统一目录
Set-Location '<仓库根目录>'
Copy-Item local-build.example.psd1 local-build.psd1  # 首次配置；本机已配置
# 编辑 local-build.psd1 填写已有 JDK、SDK 路径
.\verify.ps1 -Offline
.\verify.ps1 -Platform Windows
.\verify.ps1 -Platform Android -Offline
```

统一脚本在 Android 发布密钥缺失时停止，防止自动换签名。原平台构建脚本仍可单独使用；Android 直接调用需显式传入 `-JdkPath` 和 `-SdkPath`，不要依赖旧工程相对路径回退。

历史验收：Windows v1.5.0 的 3,858 项核心、83 项智能解析、34 项历史、33 项界面逻辑检查共 4,008 项通过；Android v1.1.0 的 18 组单元测试、60 项真机检查、Lint 和签名验证通过。Android 原真机验收覆盖 OPPO PHY110 / API 37；其他系统版本和深色界面未逐机验收。历史报告见 `android/docs/验证报告.md`，原始本机日志归档到 `.local/evidence/`。

本次归并的重新构建、安装包哈希及签名核验结果见 [整合验证](整合验证.md)。测试使用现有隔离检查；本次不安装手机应用、不读写正式历史。
