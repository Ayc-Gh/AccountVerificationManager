# 1.9.1 管理菜单修复

后续说明：本页保留当时的本地验收记录，功能已并入 1.9.2；当前保存期限界面与发布验证见 [1.9.2](v1.9.2保存期限与发布验证.md)。

2026-11-16。本地交付，尚未提交或发布 GitHub。Windows 与 Android 可见版本统一为 1.9.1，Android versionCode 为 10901。

## 问题与修复

Windows 1.9.0 点击历史记录管理菜单时，可能出现对象名为 `ContextMenuStrip` 的 `ObjectDisposedException`。原代码在菜单 `Closed` 事件中立即调用 `Dispose`，而 WinForms 的点击流程在触发该事件后还会访问下拉窗口句柄。在隔离测试进程中，以 `ToolStripItem.PerformClick()` 复现了相同异常。

历史管理和更换 2FA 的多二维码选择菜单改为使用 `DeferredContextMenu`：每个窗口复用自己的菜单，刷新条目时释放旧条目，窗口释放时才释放菜单。菜单动作通过所属窗口的消息队列执行，让菜单完成关闭处理后再打开模态对话框、更新历史列表或修改草稿。窗口已经关闭时，待执行的操作直接失效。

Android 本轮仅同步版本号及对应验收断言、说明文件，业务逻辑与 1.9.0 相同。历史文件及 `.avmx` 导入导出格式不变。本次修复没有读取、清空或迁移正式历史。

## 验证

Windows 执行 `build.ps1 -OutputDirectory release\v1.9.1`，五组共 **4,195 项**通过：基础 3,858、智能识别 83、二维码 16、历史 98、界面 140。

界面检查新增 28 项，使用独立临时历史和虚构账号，实际触发菜单点击，包括：

- 重复打开管理菜单、置顶和取消置顶、直接关闭菜单。
- 菜单关闭后打开到期编辑器并保存。
- 删除确认框取消时保留记录，确认时删除指定记录。
- 多二维码反复选择和取消，选择只更新更换草稿。
- 所属窗口释放时菜单一并释放；窗口关闭前排队的操作不会继续执行。

Android 执行 `verify.ps1 -Platform Android -Offline` 成功，42 项单元测试报告无失败或错误，最终验证复用了 Gradle up-to-date 结果；发布 Lint 为 0 错误、3 条既有警告，APK 签名验证通过。没有重新执行真机验收，也没有安装或操作正式手机应用。

Windows 日志为 `.local/verification/windows-v1.9.1-build.log`，Android 日志为 `.local/verification/android-v1.9.1-build.log`。本地交付包位于 `dist/`，Windows 可执行文件位于 `release/v1.9.1/`，源码包排除本地历史、凭据、签名材料和机器配置。

## 使用

关闭 1.9.0 后运行 1.9.1。菜单异常由应用修复，不需要开启 JIT 调试。Android 如需同步版本，使用相同签名的 APK 覆盖安装。
