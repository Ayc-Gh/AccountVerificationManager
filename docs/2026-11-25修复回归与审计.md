## Android 导出 JSON 时旋转屏幕

在修改生产代码前，本机 Android 17（API 37）模拟器分别验证了先导出 CPA 和先导出 sub2api 的情况。两次都在文档写入中实际切换屏幕方向，确认系统以新方向重建登录页，再允许写入完成。两份首个文件都能解析且内容正确，随后均在等待两个导出按钮恢复时失败。

导出请求现在由当前登录会话持有。请求记住本次选定的文件格式，文件选择器返回的结果按请求编号匹配。写入通过应用级 `ContentResolver` 在后台执行，当前登录页收到完成或失败结果后更新提示和按钮。旋转后不再从页面保存状态恢复单独的“忙碌”标志。进程被回收后，页面保存状态只恢复服务和登录方式。

## Gradle 弃用提示与 Windows 单测路径

升级前在原中文工作区强制运行 JVM 单测，Gradle 9.9.2 同时报告 `Task.project` 和 `Configuration.setVisible` 弃用。对照日志在 `.local/verification/20261125-gradle-deprecations/`。

### Windows 构建与配置缓存

Gradle 9.9.2 使用 Windows 本机编码写测试进程的参数文件。在本机 GBK 下，原中文仓库可以直接执行 64 项单测。含 emoji 的独立目录则复现十个测试类全部加载失败。另一次对照发现，在 `doFirst` 中替换类路径，即使已经复制了测试类文件，启用配置缓存后，测试进程仍可能收到旧路径。[Gradle 对参数文件编码的修复记录](https://github.com/gradle/gradle/issues/30304)

现在在配置阶段绑定测试进程的类路径，并保留原编译任务依赖和条目顺序。只有本机编码无法表示的文件或目录才由独立任务同步到临时目录。任务通过注入的 `FileSystemOperations` 执行复制，目录按项目和测试任务隔离，文件名由源路径标识及限长的可读尾名组成。原中文路径直接使用编译产物。

在原中文仓库和含 emoji 的独立工作区，各自连续两次执行 `:app:testDebugUnitTest --configuration-cache --rerun-tasks --warning-mode fail`。四次均实际运行 10 个类、64 个测试，0 失败、0 跳过。两处均验证了缓存首次存储和第二次复用。含 emoji 的目录使用 ASCII 路径下的同版官方 Wrapper 启动，本机 Windows Java 启动器无法直接打开绝对路径含 emoji 的 Wrapper JAR。原中文仓库使用仓库自带的 Wrapper。额外的文件系统检查验证了不同目录的同名长文件内容正确，输出目录或其父目录被 NTFS 目录联接重定向时，任务在同步前停止。详见 `cc-Chinese-final-*.log`、`emoji-verified-*.log` 和 `agp-probes/staging-final-safety.log`。

### Android 构建插件与运行时依赖

Google 已在 AGP 9.5 系列修复 Android 插件自身调用 `Configuration.setVisible` 的问题。仅升至稳定版 9.5.2 后，构建栈仍指向默认加载的 Kotlin Gradle 插件 2.2.10。按 Google 公布的方法在构建脚本中指定 KGP 2.4.21，并通过 Kotlin 的 `coreLibrariesVersion` 保留应用运行库 2.2.10。升级前后 Release 运行时的 28 个外部组件及依赖树完全一致。插件 JAR 的 SHA-256 与各自官方 Maven 元数据一致。[Google 的 AGP 修复记录](https://developer.android.com/build/releases/agp-9-5-0-release-notes) · [Google 的 KGP 升级方法](https://developer.android.com/build/releases/agp-9-0-0-release-notes#upgrade-to-a-higher-kgp-version) · [Kotlin 运行库版本配置](https://kotlinlang.org/api/kotlin-gradle-plugin/kotlin-gradle-plugin-api/org.jetbrains.kotlin.gradle.dsl/-kotlin-top-level-extension-config/core-libraries-version.html)

JetBrains 为 KGP 2.4.21 公布的完整测试矩阵最高覆盖 Gradle 9.7.0、AGP 9.3.1。这里使用的 Gradle 9.9.2、AGP 9.5.2 组合由本仓库的构建、签名、设备和跨端回归验证。AGP 仍提示中文路径开关 `android.overridePathCheck=true` 为实验选项，构建保留原有的提示级别。[JetBrains 兼容矩阵](https://kotlinlang.org/docs/gradle-configure-project.html)

### 完整回归与发布隔离

Windows 七组 4,443 项检查全部通过，两组长字段记录均完成 Java 写出、Windows 导入与加密存储重开、Java 读回。详见本轮证据目录中的 `final-verified.log`、`lint-results-release.xml`、`manifest-comparison.log`、`release-probe.log`、`windows-build.log` 和 `interop.log`。

Android 8.0（API 26）设备回归发现，重新识别已有记录后，存储中仍有一条记录，但界面可能尚未重新绑定该记录。旧测试立即点击“更换 2FA”，有机会检查到上一次已关闭的弹窗。设备测试现在会在主线程等待按钮启用，等当前弹窗获得焦点后才启动相机；相机返回时继续核对原弹窗与原加密记录。文件导入的对话框也等待按钮启用并可点击。最终 QA 包冷启动耗时 1,393 毫秒，完整设备回归 259 项通过，另行重跑的旧版登录专项 5 项通过，两次返回码均为 `-1`。专项与完整回归有重叠。详见 `api26-full.log` 和 `api26-autofill.log`。
