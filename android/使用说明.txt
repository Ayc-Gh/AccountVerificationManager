账号验证管家 1.10.0 本地测试版：
历史记录 → 管理 → 登录并生成 CPA / sub2api。选择 ChatGPT / OpenAI（Codex）或 Claude / Anthropic，再选历史账号自动填充或官方网页手动登录授权。
账号须使用实际登录邮箱，授权结果须与所选历史账号一致。自动模式只填写账号、密码与验证器动态 2FA；在网页点击继续、完成邮箱验证码/人机验证并确认授权。Claude 采用邮箱链接等登录方式时仍需在官方网页完成。
登录成功后可分别生成 CPA JSON 和 sub2api JSON。文件含可用登录令牌，不含账号密码或 2FA 密钥；这与原有密码加密 .avmx 历史备份不同。妥善保管 JSON，不要公开分享。
登录结果仅在内存保留，不写入历史；关闭登录窗口、记录删除/到期/替换、15 分钟会话超时或令牌到期即失效。导出文件是独立副本，不随源记录删除。
解析、验证码和本地历史继续离线运行；仅主动登录时连接官方网页和官方授权服务。
Windows 自动模式需要已安装 Edge 或 Chrome，使用独立临时浏览器窗口；手动模式打开系统默认浏览器。
Android 自动模式需要 Android 9+ 与官方 Chrome / Edge，首次需在系统启用本应用自动填充服务，Chrome 中选择使用其他自动填充服务，点击建议后填写；手动登录支持 Android 8+。不改变手机系统设置，需由用户在设置中选择。
如果未自动返回，复制网页地址栏中完整 localhost 回调地址回到管家完成登录；不要把回调或文件发送给他人。
本地测试版尚未发布 GitHub。Android 真机检查使用虚构数据，Windows OpenAI 真实登录及两种 JSON 保存已通过；Claude 按用户要求停止真实账号核验。实际服务端导入尚未验收。

账号验证管家 1.9.2 更新：
保存期限改为输入数字后在旁边选择分/时/天/周/月，接受 1 至 999999 的整数；超出可保存日期范围会提示缩短期限。
1 天=24 小时，1 周=7 天，1 月=30 天。从首次保存新记录时开始计时，重复解析保留原期限。历史管理中保存新期限则从修改时重新计时；不勾选表示永久保留。
包括 1.9.0 的历史管理与密码加密多选导入导出，以及 1.9.1 的 Windows 菜单异常修复。

账号验证管家 1.9.1 更新：
与 Windows 管理菜单修正版同步版本号。Android 功能与 1.9.0 相同，使用原签名覆盖安装可保留本机历史。

账号验证管家 1.9.0 更新：
首次解析前点击“保存期限”，可选本地日期时间；默认永久保留。只对新记录使用该设置，重复解析保留原有期限和置顶状态。
历史记录点击“管理”，可修改/取消到期时间、单条删除、置顶/取消置顶。应用运行时自动清理到期记录，关闭期间到期的记录在下次启动清理；置顶不会阻止到期。删除或到期后清除当前已恢复结果与相关更换草稿。
历史页支持“多选导出”和“加密导入”。导出时多选记录并设置文件密码，生成 .avmx 文件；导入时输入文件密码、选择要导入的记录。文件包含账号、密码、2FA 密钥、otpauth 链接、名称、期限、置顶及验证码参数，不包含当前验证码。Windows 与 Android 可互导支持的 TOTP 记录；Android 不接受 HOTP。
导入重复记录保留本机内容，已到期记录跳过；容量不足时整批拒绝，不覆盖或挤掉现有记录。最多十条历史，置顶优先保留；十条全部置顶时需先取消置顶或删除，才能保存新记录。
导出文件密码不保存，遗忘后无法解密文件。导出文件是独立副本，源记录删除不会删除此前导出的文件。导入仍按原到期时间处理。
本地历史写入 v4，请继续使用 1.9.0 或后续版本。上述功能已包含于 1.9.2 发行版。

﻿账号验证管家 1.8.0 更新：
新增“更换 2FA”：识别或恢复目标历史后，在验证码卡片右上角进入；可复制旧验证码、粘贴新密钥或拍照/上传新二维码，预览并复制新验证码后保存替换。保留原账号、密码、名称和列表位置。

1.7.0 起支持历史命名：
历史记录新增“命名 / 改名”，最多 40 个字符。名称在本机加密保存，重启后保留，再次识别相同记录时保留名称。留空保存恢复默认显示，取消不保存。名称不改变账号、密码、密钥、验证码参数或复制内容。兼容旧历史；新版保存后请继续使用 1.7.0 或后续版本。

账号验证管家 Android v1.10.0
==========================

安装与升级
安装“账号验证管家-v1.10.0.apk”，支持 Android 8.0 及以上，无需 Root。仅主动登录按需联网；自动填充需 Android 9+。
沿用 v1.0.0 发布签名，可直接覆盖安装，保留本机加密历史。无需卸载旧版。

智能识别
粘贴以下任意一种内容，点击“识别并生成”，或使用“粘贴并解析”：
1. 账号记录：账号----密码----2FA密钥。
2. 纯 Base32 2FA 密钥，不需要补写账号、密码或分隔符。
3. Authenticator URI：otpauth://totp/...，不需要手动提取 secret。

示例（公开测试密钥和虚构账号）
demo@example.com------Demo%_Password*-----GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ
GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ
otpauth://totp/Example:alice%40example.com?secret=GEZDGNBVGY3TQOJQGEZDGNBVGY3TQOJQ&issuer=Example&algorithm=SHA256&digits=8&period=60

Authenticator URI
支持 otpauth://totp/，读取账号标签、发行方 issuer、Base32 密钥 secret。
可选参数：algorithm=SHA1/SHA256/SHA512，digits=6/8，period=正整数秒。
省略参数时采用 SHA1、6 位、30 秒；填写后按实际参数生成验证码和倒计时。
支持百分号编码和中文标签，保留邮箱中的加号，例如 alice+test@example.com。
缺少密钥、重复参数、发行方冲突或参数无效时明确提示，不会自动退回默认参数。
支持拍照或上传二维码图片；暂不支持 HOTP 计数型 URI、otpauth-migration 批量迁移 URI/二维码。
URI 在本机处理，不打开链接、不请求网络。

账号记录
自动识别连续 3 个及以上符号，两处的符号和数量可以不同。
使用第一处和最后一处分隔符，保留密码内部符号、大小写和首尾空格。
例如账号------密码*-----密钥会保留密码末尾的 *。
复杂边界可切换“手动分隔”，按原样填写分隔符，支持单字符、多字符和文本。
手动模式仍可识别独立密钥和 URI；明确匹配两处手动分隔符的内容按账号记录处理。
纯密钥和账号记录使用默认 SHA1 / 6 位 / 30 秒。
Base32 支持小写、分组空白和标准末尾 = 填充。

结果与复制
仅展示实际存在的字段；纯密钥不显示账号或密码，URI 不虚构密码。
验证码旁显示类型或账号及实际算法、位数、周期；复制时重新计算当前验证码。
“复制全部”包含实际存在的发行方、账号、密码、密钥、URI 验证参数和当前验证码。
URI 提供“复制 Authenticator URI”，输出规范化链接并保留算法、位数和周期。
修改输入、模式或手动分隔符后旧结果立即失效，请重新识别。
密码默认隐藏，可点击“显示”；回到后台时恢复隐藏。

最近 10 条历史
成功识别后自动保存最近 10 条，升级保留旧版账号记录。
保存输入类型、密钥、实际字段和 TOTP 参数，不保存过期验证码。
相同类型、字段、密钥和验证码参数的记录再次识别时置顶，不同参数视为不同记录。
点击历史可恢复，快捷复制按钮按类型显示：
账号记录：账号 / 密码 / 验证码 / 整组。
URI：有账号时提供账号，否则省略；支持密钥 / 验证码 / 整组。
纯密钥：密钥 / 验证码 / 整组。
“整组”只复制实际存在的发行方、账号、密码和当前验证码，不包含密钥。
“清空”只清除当前内容；“清空历史”确认后删除历史，当前结果保留。

本地数据
历史使用 Android Keystore 的 AES-256-GCM 加密保存在应用私有目录，禁用系统备份。
卸载会删除数据；历史不是跨设备备份。Windows DPAPI 历史不能直接导入。
损坏文件会被保留并提示；明确清空历史后可重新保存。
旋转屏幕保留内存结果及 URI 参数，进程退出后从历史恢复。
复制内容会进入系统剪贴板，受系统和输入法的剪贴板设置影响。
请保持手机系统时间准确。
